## North star

Build an original, proprietary multiplayer class-based objective game: Corgis vs Cats. Six soft-counter archetypes combine gunplay, mobility, area control, class-gated terminals, limited vehicles, and match-scoped Upgrade Cores. The server owns every competitive truth. The experience earns breadth only after its smallest combat loop makes humans want another match.

Delivery is optimized for verified `ACTIVE → DONE` cycle time and time to the first human-completed authoritative match. Artifact count, harness size, and worker count are diagnostics, never success measures.

### Repeatable loops

First-playable loop:

```text
Spawn → move/aim/fire → deal/receive authoritative damage → die/respawn
→ change team score → reach result → choose to rematch
```

Full product loop:

```text
Join → choose a class/job → contest an objective → use team resources
→ adapt class/position/loadout → resolve the match → rematch
```

## Finish-line metric contract

Metrics are defined now so later agents cannot move the goalposts.

| Term | Locked definition |
|---|---|
| Qualified player | A real human outside the core development team; bots, automated runs, staff/test accounts, duplicate identities, and abandoned pre-match joins are excluded |
| Completed match | The player enters active play before the configured late-join cutoff and reaches the authoritative results state; disconnects count as incomplete unless a later reconnect restores and completes that same match |
| Same-session requeue | The next authoritative active-match start occurs within 10 minutes of the prior authoritative results state; request/queue timestamps remain diagnostic only |
| Different day | A distinct UTC calendar date |
| Engaged player | A qualified player with at least 2 completed matches on different days, or at least 3 completed matches total |
| Goal | 100 distinct engaged players |

The 100-player goal is not met by registrations, Discord members, downloads, bots, survey intent, or match starts. Instrumentation must preserve a privacy-safe stable player key and authoritative match completion records before external counts are claimed.

The engaged-player query must pass deterministic boundary fixtures: two completions on one UTC day is not engaged; two on different UTC days is engaged; three on one day is engaged; incomplete matches, disallowed late joins, bots, staff, duplicates, and abandoned joins are excluded; a reconnect that completes the same match counts once. Every claimed player links to qualifying match IDs, UTC timestamps, build IDs, and one privacy-safe stable key.

## Product red lines

- Multiplayer-first. Never build a single-player system and “network it later.”
- Server authority for health, damage, death, score, teams, spawn, objectives, inventory truth, ammo, cooldowns, terminals, cores, vehicles, and win conditions.
- Clients own input, camera, prediction where supported, UI, and cosmetic feedback; they never decide competitive outcomes.
- Soft counters only: target roughly 60/40 skilled matchups, never hard “cannot fight” lockouts.
- No permanent combat-power progression across matches.
- Zero Conker/Rare expressive IP: no copied names, silhouettes, animation language, VO, jokes, props, or presentation.
- One excellent weapon before class breadth; three proven classes before six; terminals before vehicles; one map before a second.
- Graybox until the first-playable queue test passes. Art polish never repairs an unfun combat loop.
- Free-first does not mean unreviewed. Every external asset or tool clears provenance, license, security, compatibility, performance, and rollback checks.
- Humans certify fun. Agents can prove correctness and surface evidence; they cannot self-certify the queue answer.

## Multiplayer evidence contract

Every competitive feature must prove all of the following before DONE:

1. **Authority:** identify the server-owned source of truth, accepted request path, validation, mutation point, and replicated observation.
2. **Negative case:** show an invalid, duplicate, stale, out-of-order, or non-owning client request is rejected or harmless.
3. **Lifecycle:** prove spawn, death/reset, match transition, disconnect, and late-join behavior relevant to the feature.
4. **Network matrix:** record exact emulation settings and observed behavior at these target RTT/loss cells:
   - 20 ms / 0% loss;
   - 80 ms / 1% loss;
   - 150 ms / 3% loss.
5. **Degradation:** before an external promotion, run a non-blocking discovery pass at 500 ms RTT / 10% loss and record failures; the game may feel poor, but it must not corrupt authoritative state or deadlock the match.
6. **Traffic evidence:** capture Networking Insights whenever bandwidth, replication frequency, relevancy, or RPC volume is used to justify a decision.

Network Emulation must be calibrated and recorded as incoming/outgoing settings; a label such as “150 ms” without the actual configuration is not proof.

### Phase 3 — Three-Archetype Strategy Proof

**Outcome:** Three class jobs create visible team decisions without weakening the core weapon loop.

## Quality and promotion policy

Evidence labels:

- **R — Repository:** code/config/docs and deterministic checks.
- **E — Engine:** identified compile, editor, PIE, standalone, dedicated, cook/package, Insights, or rollback observation.
- **H — Human:** feel, comprehension, comfort, readability, and queue evidence.

Every READY item defines the minimum cells before work begins. External builds require a release decision:

- **GREEN:** required tests/evidence pass; no blocking defect; monitoring and rollback are ready.
- **YELLOW:** bounded non-critical risk with named owner, workaround, approval, and retest.
- **RED:** critical path failure, unknown authority/crash risk, missing rollback, or unstable environment; do not promote.

Regression protection stays proportional: deterministic combat/state math at unit level, authority and lifecycle at multiplayer integration/runtime level, and feel/readability through human play. No fragile full-match automation substitutes for focused lower-layer tests or human evidence.

### Verification ladder

Advance strictly from the cheapest proof to the most expensive:

1. **L0 — Compile/static/local:** compile and static contracts plus deterministic local validators.
2. **L1 — Negative strength:** every required negative mutant passes, including regressions for prior RED defects.
3. **L2 — Network smoke:** one 80 ms / 1% loss listen-server plus one remote-client smoke passes.
4. **L3 — Required matrix:** the complete 20/0, 80/1, and 150/3 matrix passes with exact settings and required lifecycle cases.
5. **L4 — Bound LKG:** exact-source last-known-good passes and publication remains fail-closed without replacing a prior good pointer on failure.
6. **L5 — Independent RED:** a fresh verifier attacks the fixed evidence identity and returns no promotion-blocking defect.

Do not advance while a lower layer fails. Classify a failure as runtime, evidence generation, validator, or publication; apply one bounded repair and rerun only the smallest affected layer unless runtime behavior or the bound evidence identity requires full regeneration. Freeze the wrapper and negative-mutant inventory before the expensive matrix.
