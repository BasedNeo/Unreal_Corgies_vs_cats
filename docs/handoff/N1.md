# N1 handoff — Bots climb: nav links to The Rooftops (Wave 5)

Status: **done for integration.** Bots now treat the garage roof and the crow's nest as places they can go. A small link
layer (`src/sim/ai/nav-links.ts`) joins the ground grid and **decks** (elevated surfaces flooded into their own small
nav grids) through **links**: hop sequences validated with the real `stepCharacter` for each movement profile. The
brain plans across grids, runs a link leg by leg (hop, double jump, air-steer, land), retries a missed hop once, then
falls back. **Overwatch room bots in TDM and yard-skirmish now take a roof perch by themselves.**

No shared contract changed. `stepCharacter`, `tactics.ts`, `drive.ts`, `src/shared/**` are untouched. The tactics hook
for adventure roof steps is a paste-ready snippet (§4).

What a climb looks like: the bot walks to the route's first standing point, stops on it, then per leg jumps at once,
double-jumps at the apex (holding Jump for full height), air-steers onto the next crate or plank, settles and goes on.
Descending walks off each ledge with "timed arrival" steering (the speed that reaches the point as the fall lands).

## 3. API for B2 and tactics

```ts
import { canReach, navLevelAt } from '../ai/nav-links';   // (or via ai/index.ts, see §4.2)
import { holdPerch } from '../ai/brain';

canReach(sim, e, x, y, z): number      // planner cost (m) for bot e to stand at feet (x, y, z); Infinity = no validated
                                       // route. A point up to 1 m above a surface snaps down to it (a zone's minY).
navLevelAt(sim, x, y, z): number       // 0 ground grid · 1 garage roof · 2 crow's nest · -1 on none (a crate, mid-air)
holdPerch(sim, e, { id?, x, y, z, yaw? } | null)   // climb to and hold a spot (scans ±30° around yaw); null clears
e.ai.perch                             // PerchGoal: reachedAt (tick, -1 = not yet), pauseUntil (unreachable: patrols)
e.ai.nav                               // NavBot: link (-1 = none), done / misses / fallbacks / contested counters
```

- **A tactics goal on the roof is climbed to.** The brain's patrol-goal branch now passes `t.gy` to `steerTo`. When
  `t.gy` stands more than 1.5 m over the ground grid, the link layer plans across grids. With no route, it walks
  below the goal as before. Today every tactics goal writes a ground height, so nothing changes until a goal sets an
  elevated `t.gy`. Sentry `post` goals are excluded.
- **B2b (plane):** to send a bot to the Rooftop Hangar, set a `step` goal at the terminal with `t.gy = GARAGE_ROOF`
  (the pad is at `GARAGE.x + 8.3, 7.2, GARAGE.z - 8.2`). The test "a tactics goal up on the roof" does exactly this.
  - `canReach(...) < Infinity` tells you whether that bot has a route.
  - A seated bot (`EFlag.Mounted`) drops any link it was running, so the vehicle owns its input.
- **Descending is automatic.** A bot on a deck with a ground goal takes a descent or a drop link.

## 5. Ground-follower fixes in brain.ts (why the soak moved)

The first soak with climbing snipers had a Warden stuck exactly 5.0 s at (4.7, 5.7), wedged against the centre
trampoline's cylinder collider. That's a latent ground-nav bug; the TDM fight just played out differently.
- **The cause.** The follower passed a waypoint from up to 0.8 m away, then headed for a corner 40 m off on a line that
  clipped the cylinder. Rapier's controller deadlocks there: zero velocity even when pushing along the wall. The
  random detour also walked straight back into it.
- **Fix 1.** A waypoint is passed only once the next one is in a straight walkable line from where the bot is.
- **Fix 2.** A bot wedged in a closed cell detours to the nearest open cell first; other detours prefer a straight-line
  reachable cell.
- **Result.** In open ground nothing changes. Soak stuck max went 0 / 5.0 / 1.5 → 0 / 1.5 / 1.0 s (yard-skirmish /
  TDM / core-rush); the HEAD baseline was 0 / 0.5 / 1.5.
- **Soak results.** core-rush has no Overwatch in its lineup and was identical to HEAD (25:40) before these two fixes;
  it is 19:40 after them.

## 7. Known issues

- **One-off cost.** Link validation runs 45–100 ms per movement profile, on the first need in a process (a
  marksman's first perch pick, deferred to ≥ 1 s, or a bot ending up on a deck).
  - With the nav grid build, the first second of a West Yard match can have a 150–400 ms tick. The soak's p95 hides
    it; its max shows it.
  - Pre-warming at room creation would move it before the match.
- **Only the garage roof and the crow's nest are decks.**
  - The Corgi porch deck (stairs) and the shed roof (cat tree → plank) have no links: no goal needs them yet.
  - A route entry would add them. They are not auto-discovered.
- **Snipers are simple.** A perched bot holds until it dies. It doesn't rotate perches, crouch behind the parapet or
  react to a flanker climbing up, beyond turning and shooting.
  - Two Overwatch bots of one team can share a perch after a death: a claim is only checked among living teammates.
- **Contested means shot on the link.** An enemy camping the roof arrival without shooting doesn't stop a climb.
- **Link runner and validation agree only while the world is static.**
  - A standing destructible near a route is included in validation (conservative).
  - Knockback mid-hop counts as a miss.
- **Profiles.** Archetype speed multipliers (kitten 1.2×, brute 0.85×) are separate profiles. PvE cats only validate
  when they need a link (they have no elevated goals).
- **Drops.** Drop links land on open ground ≥ 1 cell from walls. The east-gap drop lands on the scaffold and fails
  validation, so it's dropped, not used.
