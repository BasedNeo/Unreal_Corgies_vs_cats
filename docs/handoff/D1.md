# D1 handoff — Determinism across rooms in one process

Status: **fixed, not committed** (lead integrates; nothing staged). Rooms no longer leak into each other. The shared nav
caches held per-room state: the **shared nav grid** (and the N1 deck grids and link set built on top of it) was probed
against every collider of whichever room built it first. That included the room's **terminal kiosks**, and any kart,
plane or barrier standing there at that moment. The kart grid's shared "flat" mask had the same kind of leak. Every
later room of the same world then planned on the first room's kiosks.

Now the shared grids are built from the static world only (a pure function of WorldData). Kiosks close their cells per
sim (`setNavFixture`, on the ground grid and on that sim's view of the decks). For the room that is first in its
process, the grid comes out cell for cell as before, and chapter 6's signature is bit-identical before and after. On
top of that the shared grid builds about 4× faster warm (2× cold): the probe's analytic prefilter works again.

## 1. Culprit

`src/sim/ai/nav.ts` `buildNavGrid()`: the grid is cached by world signature and shared by every sim of the world. Its
capsule probe used `WORLD_RAY_FILTER` (World | Vehicle layers) with the predicate `notDestructible`, so it saw:

- **the building sim's terminal kiosks** (World layer, `TERMINAL_GROUPS` / `WORLD_GROUPS`, no rigid body). Which ones
  exist depends on the mode:

  | mode | kiosks at tick 1 |
  |---|---|
  | team-deathmatch, core-rush, yard-skirmish | 2 Kart-O-Matics, 2 Ordnance Kiosks, the Rooftop Hangar |
  | adventure (every chapter) | 2 Ordnance Kiosks, the Rooftop Hangar |
  | boss-rush | 2 Ordnance Kiosks |

- anything else standing in that sim when the grid was built (karts, planes, Squeak Barriers / barricades).

The kiosks also broke the analytic prefilter. `exact = staticCount !== 1 + props + cylinders` was true in every real
room, so all 39,203 cells were Rapier-queried (~200 ms).

The same leak sat in two more places:

- **N1 deck grids** (`buildDeckGrid`, cached inside the link set keyed by the shared grid). Their filter `staticOnly`
  meant "no rigid body", but kiosks, karts and planes have none. So the Rooftop Hangar (and a plane parked on the roof)
  was baked into the roof deck of whichever room built the link set first: 413 walkable cells when a room with the
  hangar built it, 417 when boss-rush did.
- **`src/sim/ai/drive.ts` `flats`**, the kart grid's flat mask. It is keyed by the grid's shared `ground` array but was
  computed from the calling sim's walk (skipping its closed cells). So a kiosk or a standing destructible of the first
  sim that needed karts stayed undrivable for every sim, even after the destructible broke.

Ruled out on the way (bisected, or pure by construction): the link sets' `profiles` and validation `scratch` world (built
from WorldData only, env clock 0), `cellCache` (pure: base-grid cells per box list), the kart `navs` (per grid object:
per sim once it has an overlay), the A* stamps, and the stat counters (`pathStats` / `driveStats` are telemetry only).
The same goes for `world/systems.ts` `variants` / `baseOf` (immutable per entity base), the cached projectile defs and
plane hulls (never mutated), the module-level Sets (cleared per use), and the blast/hit listener lists (registered
once at import).

## 3. The fix (6 source files)

- `src/sim/world/build.ts`: `buildStaticWorld` tags every collider it makes (`__static`), and there is a new
  `isStaticWorldCollider(c)`. It is purely additive: same colliders, same order, same groups. Prediction and the N1
  scratch world are unaffected.
- `src/sim/ai/nav.ts`:
  - The shared ground grid and the deck grids probe `staticWorldOnly` (`isStaticWorldCollider`). `staticColliders()`
    counts only those, so the analytic prefilter works again (4,251 queries instead of 39,203).
  - `setNavFixture(sim, key, boxes)` is new: a per-sim world fixture. It is a second cover map in the X1 overlay, so it
    closes ground cells exactly like a blocker. `navBlockerStats().blockers` still counts destructibles only.
  - `deckGridFor(sim, deck)` is new: the sim's copy of a shared deck with its fixtures' cells closed. It is built once
    per sim and fixture version, and returns the shared deck when no fixture touches it.
  - `navFixtureVersion(sim)` is new.
  - `setNavBlocker`'s body moved into `cover()`, shared by blockers and fixtures. The logic is unchanged.
- `src/sim/ai/nav-links.ts`: `navLinksFor(sim)` / `navLinksIfBuilt(sim)` return the sim's view of the shared set: its
  own decks from `deckGridFor`, everything else shared by reference. It is cached per sim and fixture version, and is
  the shared set itself when no fixture touches a deck (boss-rush). `profileLinks` and `scratchFor` resolve a view to
  its shared set, so validations and the scratch Rapier world stay one per world.
- `src/sim/ai/drive.ts`: `flatFor` no longer reads the grid's walk. It skips only cost ≠ 1 cells, which makes it a pure
  function of ground, costs and props. `buildKartNav` already ANDs the sim's walk on the cell, its 4-neighbours and its
  diagonals, so the kart grid is unchanged for the sim that builds it.
- `src/sim/vehicles/systems.ts` `spawnTerminal` and `src/sim/interact/ordnance.ts` `spawnOrdnanceTerminal` each
  register their kiosk box with `setNavFixture` (one line each, plus an import of `../ai/nav`; `nav.ts` doesn't import
  them back). This is the X1 pattern: the owner registers its obstacle.

## 5. Performance

Measured on the shared 4-core machine (load 7–11 from other lanes). The scripts are in my session scratchpad, not in
the tree: `perf-nav.mts` (cold, fresh process), `d1-perf-warm.mts` (warm), `d1-navdigest.mts` (the digests in §2) and
`matrix.sh` (the §2 matrix). Each takes `ROOT=<tree>`. The TDM room is at tick 1 with 4 bots (3 movement profiles).

| cost | HEAD `e452b19` | fixed |
|---|---|---|
| **shared nav grid build, warm** (`buildNavGrid`, best of 5, 2 runs) | 112.5 / 115.7 ms, 39,203 Rapier queries | **25.6 / 27.2 ms, 4,251 queries** |
| shared nav grid, first build in a fresh process (cold JIT, 3 runs) | 207–250 ms | **103–138 ms** |
| link set build (decks + links), first | 100–127 ms | 101–109 ms |
| profile validations (3 profiles), first | 232–301 ms | 231–242 ms |
| kart grid, first (flat mask + grid) | 59–94 ms | 62–84 ms |
| **second room of the same world** (best of 5): overlay grid · link view · kart grid | 2.1 · 0.2 · 4.4 ms | 2.2 · 0.3 · 4.3 ms |

- The shared caches keep their whole win: a second room pays ~7 ms for its per-sim copies, as before.
- The link view costs ~0.1 ms more per room: the roof deck copy with the hangar closed.
- The first build of the shared grid is 4× cheaper warm and about 2× cheaper cold. The probe no longer sees kiosks, so
  the analytic prefilter works again: 4,251 queries instead of 39,203. B2's "nav grid's 180–200 ms" becomes ~100 ms
  cold, ~26 ms warm.
- The flat mask now runs its ledge test on cells that are closed in the base grid too. That cost is within the noise
  of the kart grid's first build.

## 7. Behaviour changes and known issues

- **The first room in a process plays exactly as before.** Its grid is the old one (0 cells differ) and ch6's hashes
  are identical. Later rooms now plan on their own mode's kiosks instead of the first room's.
- **Karts, planes and barriers** standing when a grid or deck was first built are no longer baked into it. That was
  only possible when a bot's first link or kart need came after one was vended or raised.
- **Kart grid after a break.** A cell under a destructible that stood at a sim's first kart need now becomes drivable
  once the destructible breaks. Before, `flats` kept it undrivable for good, which defeated B2's "rebuild when the
  walkable count changes".
- `setNavFixture` is for fixtures that never move: the kiosks, which are "never removed". A future movable obstacle
  that bots should walk around belongs in `setNavBlocker` (ground only, like X1). A future fixture on a deck needs
  `setNavFixture`, or bots on the deck will plan through it.
- Not audited beyond what the matrix covers: module-level scratch objects in `ai/tactics.ts` and `ai/brain.ts` that are
  written before each read. The matrix exercised all five modes and every chapter against three different histories
  and found nothing else.
