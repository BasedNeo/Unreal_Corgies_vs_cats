# L5 handoff — HUD, audio & FX ("juice")

Lane L5, Wave 1. Everything is exposed as factories; nothing in `main.ts`, shared contracts or other lanes' paths
was edited. `createHud(ui)` still works with the old single-argument call, so the current `main.ts` compiles and
runs unchanged — the steps below switch on menus, FX and audio.

## 2. APIs

### HUD — `createHud(root: HTMLElement, actions?: Partial<HudActions>, opts?: { clock?: () => number }): Hud`
Appends `#cvc-hud` to `root` (does **not** wipe `root`, so the lead's `Nameplates` stay).

| Member | Notes |
|---|---|
| `update(m: HudModel)` | every frame. Old fields unchanged. **Optional additions:** `states` (entity map → damage direction, feed names), `respawnIn` (s), `ability {id, cooldownLeft, cooldownTotal}`, `magSize`, `reloadFrac` (0..1), `showDebug` (default true). Without them the HUD estimates (respawn 5 s, reload 1.6 s, ability cooldowns from `ui/strings.ts`, mag = largest ammo seen for the weapon). |
| `onGameEvent(ev)` | hit markers (white / gold crit / red X kill), damage-direction arcs, kill feed, death screen killer, reload/ability timers, pickup/score toasts |
| `notice(text)` | toast (wire bus `notice`) |
| `hitMarker(kill, crit?)`, `damageFlash(amount)` | kept from the skeleton |
| `showMenu(open, view?: 'main' \| 'settings')`, `menuOpen` | main menu overlay |
| `setScoreboard(open)` | force; Tab and gamepad Back (button 8) are handled internally; auto-shown after a match ends |
| `settings` | persisted `Settings` — read at boot to configure input/audio/quality |
| `setWeaponIds(ids)`, `setUiSound(fn)` | weapon table; UI click/hover sounds (`audio.ui`) |
| `dispose()` | |

`HudActions = { play(opts: PlayOptions), chooseClass(cls), chooseTeam(team), setSetting(key, value) }` with
`PlayOptions = { mode: 'offline' | 'online', server?, name, team: TeamId | -1, cls }`. `setSetting` is called **after** the HUD
has saved the change. `play` runs synchronously inside the click/keypress, so `requestPointerLock()` and `audio.unlock()` are
allowed there. With actions provided, the click-to-play overlay also gets SETTINGS and MAIN MENU buttons.

### FX — `createFx(scene, camera, views: MuzzleSource | null, opts?): Fx`
`views` is `EntityViews` (structural match on `get(id)?.avatar.muzzleWorld(v)`). `opts`: `solidCapacity` (1400),
`glowCapacity` (700), `wordCapacity` (14), `quality`, `heightAt(x, z)` (pass `worldData.height` for bouncing debris), `seed`.

| Member | Notes |
|---|---|
| `update(dt, states?, localId?)` | real dt; also drives continuous emitters (zoomies dust from `Sprinting+Grounded` states, tennis-ball trails for `EntityKind.Projectile`) |
| `onGameEvent(ev, ctx?)` → `FxReaction {shake, hitStopFrames}` | spawns FX; the returned object is reused — read it immediately. Hit-stop is already requested internally |
| `hitStop(frames?)` → scale | request (optional) + read the presentation time scale (0.04 frozen … 1). Apply to presentation only |
| `setWeaponIds(ids)`, `setQuality('low' \| 'medium' \| 'high')` | density 0.45 / 0.75 / 1 |
| `stats` | `{solid, glow, words, drawCalls, cpuMs, peakCpuMs}` — put it in the debug hook if useful |

Draw calls: 3 total (solid particles, glow particles, words) — one per system. FX meshes stay visible with 0 instances so
their pipelines compile at load instead of hitching on the first shot.

### Audio — `createAudio(opts?: { maxVoices = 28, autoUnlock = true, music = true }): GameAudio`
`update(camera, states, localId, dt)` (listener = camera, footsteps, music mix) · `onGameEvent(ev)` · `unlock()` ·
`setVolumes({master, music, sfx})` · `ui('click' | 'hover' | 'back' | 'open')` · `setWeaponIds(ids)` ·
`setQuality(q)` (low = equal-power panning instead of HRTF) · `intensity` · `engine` · `dispose()`.
The AudioContext is created only inside a user gesture (first pointer/key/touch anywhere, or `unlock()`), so nothing
plays and no autoplay warning is logged before the player interacts.

## 3. Wiring steps for `main.ts` (lead)

```ts
import { createHud } from './ui/hud';
import { createFx } from './fx';
import { createAudio } from './audio';

// after views / cam / input exist:
const audio = createAudio();
const fx = createFx(ctx.scene, ctx.camera, views, { heightAt: (x, z) => worldData.height(x, z) });
const hud = createHud(ui, {
  play(o) {
    void audio.unlock();
    ctx.renderer.domElement.requestPointerLock();
    if (o.mode === 'online') {           // simplest robust path: main.ts already reads these URL params
      location.search = `?server=${encodeURIComponent(o.server!)}&name=${encodeURIComponent(o.name)}&cls=${o.cls}&team=${o.team}`;
      return;
    }
    net.transport.send({ t: 'class', cls: o.cls });   // offline room is already running behind the menu
    if (o.team !== -1) net.transport.send({ t: 'team', team: o.team });
  },
  chooseClass: (cls) => net.transport.send({ t: 'class', cls }),
  chooseTeam: (team) => { if (team !== -1) net.transport.send({ t: 'team', team }); },
  setSetting: (k, v) => applySetting(k, v),
});
hud.setUiSound((k) => audio.ui(k));
// Replace WEAPON_IDS with L3's weapon table order (GameEvent.fire.wpn / EntityState.weapon index into it):
// fx.setWeaponIds(WEAPON_IDS); audio.setWeaponIds(WEAPON_IDS); hud.setWeaponIds(WEAPON_IDS);

const applySetting = (k: string, v: unknown) => {
  const s = hud.settings;
  input.sensitivity = 0.0022 * s.sensitivity;
  input.invertY = s.invertY;
  audio.setVolumes({ master: s.masterVolume, music: s.musicVolume, sfx: s.sfxVolume });
  fx.setQuality(s.quality); audio.setQuality(s.quality);   // + engine/quality.ts QUALITY[s.quality] if wanted
  void k; void v;
};
applySetting('', null);                                     // apply persisted settings at boot
if (!params.has('autoplay') && !params.has('server')) hud.showMenu(true);

bus.on('game', (ev) => {
  const r = fx.onGameEvent(ev);                             // uses the states passed to fx.update last frame
  if (r.shake > 0) cam.shake(r.shake);
  audio.onGameEvent(ev);
  hud.onGameEvent(ev);
  // keep the avatar triggers (jump/land) — DELETE the old `cam.shake(0.25)` on land; fx now returns it
});
bus.on('notice', (t) => hud.notice(t));

// in the frame loop, after `const states = net.interpolated(now)`:
const pdt = dt * fx.hitStop();                              // hit-stop: presentation only
views.sync(states, net.localEntity, pdt);                   // (sim, input, net untouched)
fx.update(dt, states, net.localEntity);
audio.update(ctx.camera, states, net.localEntity, dt);
hud.update({ local, match: net.match, roster: net.roster, fps: debug.fps, rttMs: net.stats.rttMs,
  locked: input.locked || params.has('autoplay'), backend: ctx.backend, transport: transport.kind, states });
```
Order matters for one thing only: call `fx.update/audio.update` **after** the camera update so the listener and word
billboards use this frame's camera.

## 4. Event → FX / audio / camera / HUD

Music: bed always on; groove fades in at combat intensity ≈ 0.1–0.42 (0.6 s in, 2.5 s out); stabs at 0.5–0.85.
Intensity: +0.24 hit taken, +0.08 hit dealt, +0.05 nearby fire (26 m), +0.3 nearby explosion, decays with τ = 5.5 s.

  ~600 k recipe spawns grow the heap < 96/128 KB with forced GC — 1 byte/spawn would be 0.6 MB; onomatopoeia per event
  type + cooldowns; reactions + HitStop; kill-feed ordering/limits/expiry; scoreboard sorting; settings round-trip,
  v0 migration, forward-compat, garbage repair, throwing storage; voice limiter caps/stealing/priority/prune; intensity,
  layer mix, gibberish syllables). Stable over 3 repeated runs.
- `npx tsc --noEmit` → clean for the whole project at the time of writing (labs checked with a scratch tsconfig
  including `labs/juice.ts` — clean). `node tools/check-boundaries.mjs` → PASS.
- `npm run gate:fast` → typecheck ok, boundaries ok, unit: all L5 tests pass; 6 failures in `sim-movement.test.ts` and
  `net-server.test.ts` belong to in-progress work in other lanes (none import L5 code).
- FX CPU (Node micro-benchmark, peak: 6 shooters firing every frame + blast every 20 frames, ~1375 solid particles alive):
  **mean 0.19 ms, p99 0.27 ms per frame** (update + GPU-array write), on a machine at load average ~9 on 4 cores.
- HUD JS cost per `update()` (Chromium, lab, box at load ~16): steady state **0.02–0.12 ms**; with HP, ammo and score
  changing every single frame **0.17 ms mean / 0.3 ms p95** (after replacing class-toggle + `offsetWidth` animation
  restarts with the Web Animations API — the forced reflows had cost 1.07 ms mean / 7.7 ms p95). Style writes go through a
  last-value cache; `getGamepads()` is only polled after a `gamepadconnected` event.
- e2e: `npx playwright test tests/e2e/smoke.spec.ts` **timed out** in this session (both tests wait for `__cvc.ready` /
  `frames > 60` within 60 s; the main game was rendering one frame every ~9 s at load average 12–20 from the other lanes'
  browsers). A 25 s probe of `/?webgl&autoplay&bots=0,2` with the new HUD showed `__cvc.errors: []` and no console errors.
  Re-run the full gate on a quiet machine during integration.
- Browser interaction check (Playwright, lab): arrows move focus spatially, Enter selects a class card, sliders step with
  arrows, Esc leaves settings, settings persisted as `{"v":1,...}` in `localStorage['cvc.settings']`; after a click the
  AudioContext is `running`, combat intensity rises from the event loop; no console errors or warnings.

## 7. Fonts (choice + license record)

Self-hosted OFL fonts instead of a Google Fonts `<link>`: **Lilita One** (Juan Montoreano 2011, Google Fonts v17, latin
subset, 10.7 KB) for HUD/menus and **Bangers** (Vernon Adams / The Bangers Project Authors 2010, Google Fonts v25, latin
subset, 17.2 KB) for onomatopoeia. Both SIL OFL 1.1; license texts in `src/client/ui/fonts/`. Reasons: headless Chromium
here cannot reach Google Fonts (`net::ERR_CERT_AUTHORITY_INVALID` behind the agent proxy), and the e2e smoke test fails on
**any** console error; offline play must look identical; no third-party request from the game page. If the lead prefers
the `<link>` route, swap `ensureFonts()` for a link injection — the font-family names are unchanged. Fallback stacks keep
the look chunky if loading fails.

## 8. Known issues / follow-ups

- **Weapon index mapping** defaults to `CLASS_IDS` → class primary order; call `setWeaponIds(L3 table)` on fx/audio/hud.
- **Estimates** without HudModel fields: respawn 5 s, reload 1.6 s, ability cooldowns (`ui/strings.ts`). Pass
  `respawnIn`, `reloadFrac`, `ability`, `magSize` once L3 exposes them.
- **Predicted local events**: `NetClient` emits predicted `jump`/`land` for the local player on the bus; if the authority
  also sends them, local dust/boing/thud play twice. Dedupe in L4 or skip authoritative echoes for the local id.
- Onomatopoeia are depth-tested (no info leak through walls) but pulled ≤ 1.2 m toward the camera, so they can poke
  through thin props; no screen-edge clamping.
- Audio was verified to unlock and run in headless Chromium, but a human needs to listen for mix balance (music vs SFX,
  footstep loudness, gibberish voices). Only `AudioParam` automation is used (no AudioWorklet).
- The death veil and the local player's own death poof are heavy up close; consider shrinking FX for events within ~4 m
  of the camera.
- HUD class/ability icons are placeholders in the house style; the character lane's final silhouettes may suggest better ones.
