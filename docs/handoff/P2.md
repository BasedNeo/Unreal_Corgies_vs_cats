## 1. The profile: `localStorage['cvc.profile']`

### Schema v1
```ts
{ v: 1,
  xp: number,                  // total, capped at the top of the curve
  level: number,               // always recomputed from xp (stored for readability)
  unlocked: string[],          // look ids earned, never revoked; defaults are implicit, never listed
  seen: string[],              // unlocked ids the LOCKER has shown (the rest wear a NEW badge)
  equipped: { corgi: { coat?, neck?, taunt? }, cat: { … } },   // slot → look id, validated on every read
  firstWins: string[],         // MatchState.mode ids won at least once (+ 'boss-rush', see §3)
  medals:  { [chapterId]: 'gold'|'silver'|'bronze' },   // best paw on this device (unlock rules read it)
  medalXp: { [chapterId]: medal },                      // best paw XP was paid for (the new-best bonus reads it)
  stats: { matches, wins, knockouts, steps, cores, pads, chapters } }
```

### Where things live
- **`cvc.adventure` stays where it is.** A1's chapter card writes it and the chapter picker reads it.
  - Every profile load folds its paws into `medals` (best of both, never downgraded).
  - If either key is wiped, the other still holds the paws.
- **`cvc.settings` is never read or written by the profile.** Every setting stays exactly where it was.

### Migrations (pure: `migrateProfile(raw, adventure)` in `schema.ts`)
- **v0** covers three cases:
  - no `cvc.profile` (a pre-Wave-6 device with only `cvc.adventure` + `cvc.settings`);
  - corrupt JSON;
  - an unversioned object.

  The device starts fresh (keeping any understood fields) and folds in the adventure paws with **retroactive XP**, as if each paw had been recorded once:
  - medal XP + the new-best bonus per chapter;
  - +150 for the first ADVENTURE win when there is any paw.

  `medalXp` is set, so a replay never pays for the same paw twice. The migration is written back once, on the first load.
- **v1**: every field is sanitized:
  - ids are checked against `/^[a-z0-9][a-z0-9_-]{0,47}$/`, at most 256;
  - chapter ids must be known;
  - counts are floored, clamped and capped;
  - unknown keys are dropped.

  Adventure paws widen `medals`.
- **v > 1** (a newer build): the fields v1 understands are kept.
- **Blocked or throwing storage** (private window, quota): the store keeps a session copy in memory. The game never breaks.

### Unlocks and equipping
- `evaluateUnlocks(profile, content)`:
  - It is idempotent: a second call returns the *same* object with `newly: []`.
  - It never revokes: a lower level, a lost win, a missing paw, or a look the catalogue dropped are all kept.
- `equip(profile, species, look, content)` is all or nothing. A `locked`, `unknown`, wrong-`slot` or wrong-`species` id refuses the whole change, and the profile is unchanged.
- **Reads never trust storage.** `currentLook()` returns the equipped id only while it is known, fits the species and is unlocked. Otherwise it returns C3's default, and it passes C3's `isValidLook`.

## 2. XP and the level curve (`xp.ts`, pure)

| Source | XP | Cap per match |
|---|---|---|
| Played it out (≥ 30 s in the live match) | 60 | |
| Win / draw / loss | 100 / 60 / 40 | |
| Knockout you landed (an enemy) | 10 each | 25 |
| Objective step your team completed (adventure step, Squeaker mission step) | 15 each | 12 |
| Upgrade Core you took | 10 each | 8 |
| Core Pad captured with you on it | 20 each | 10 |
| Chapter paw: bronze / silver / gold | 30 / 50 / 80 | |
| New best paw (the first on a chapter, or better than ever paid) | +40 | |
| First win in a mode (once per mode, ever) | +150 | |

A match shorter than 30 s (joined at the horn, or quit at once) earns event XP only. It gets no played, outcome, paw or first-win XP.

### Typical results
| Result | XP |
|---|---|
| TDM loss, 3 KOs | 130 |
| TDM win, 6 KOs | 220 (+150 the first time) |
| Core Rush win: 3 KOs, a pad, a core | 230 |
| First clear of a chapter | 400–560 |

### Level curve
Level 1→2 costs **100** XP (any first match: played + a loss = 100). After that each level costs **200 + 50 × (level − 2)**.

| Level | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 | 20 |
|---|---|---|---|---|---|---|---|---|---|---|
| Total XP | 100 | 300 | 550 | 850 | 1200 | 1600 | 2050 | 2550 | 3100 | 11 350 |
| Matches for this level (≈ 200 XP each) | ½ | 1 | 1¼ | 1½ | 1¾ | 2 | 2¼ | 2½ | 2¾ | 5¼ |

The cap is level 99.

## 3. API for the lead (`src/client/profile/index.ts`)

| Call | What |
|---|---|
| `currentLook(species)` | `Required<Look>` for the next spawn: `{ coat, neck, taunt }`, validated and filled with defaults. `species` is a `SpeciesId` or `'corgi' \| 'cat'`. |
| `new MatchTally()` | Builds the local player's `MatchResult`. Call `.onEvent(ev, localId)` per `bus 'game'` event and `.update(frame)` per frame; `update` returns the result **once**, at the match / chapter end, and `null` otherwise. |
| `recordMatch(result)` | Applies the result: XP, stats, first wins, paws, unlocks. It saves at once and returns the `RewardSummary` for the card. |
| `createRewardCard(ui, { sound })` (`ui/rewards.ts`) | The card. Call `.show(summary, 'chapter' \| 'match')`; it hides itself after 12 s. `.hide()` hides it at once. |
| `rewardSummary(before, after, { lines, content })` | Pure. `recordMatch` already returns it. |
| `loadProfile()`, `equipLook(species, look)`, `markLooksSeen(ids)`, `profileStore()`, `setProfileStore(s)` | The LOCKER uses these; tests and labs inject a store. |

### What the tally counts
- **Knockouts**: `death` events with `by` = you, where the victim is not on your team.
- **Steps**: `score` events for your team with reason `step` (adventure) or `objective` (mission).
- **Cores**: `pickup` events by you of a core id.
- **Pads**: `score 'took pad X'` for your team, while you stand alive within the pad radius + 1.5 m (the Zone entity with seed = X's index).
- **Outcome**: `MatchState.winner` against your team when the phase turns `ended`.
  - Adventure: `ended` + the beacon's paw. The tally waits up to 2 s for the beacon.
  - A match you only saw ended gives no result.
- **Boss rush**: its `MatchState.mode` says `yard-skirmish`, so pass `mode: 'boss-rush'` in the frame. That is how C3's Boss Rush first-win look unlocks.

## 5. U2: the LOCKER and the reward card

### LOCKER
**Where**: main menu, DEPLOY card, the button row **ROOMS ▸ · LOCKER · ⚙ SETTINGS**.
- The buttons are content-sized, so SETTINGS no longer clips.
- The LOCKER button carries two chips that take no layout space:
  - a rotated `LV n` chip;
  - a red count of new looks.

**The view** (in the right card, like SETTINGS and ROOMS):
- **Header**: LOCKER · "looks never change stats" · "3 new looks".
- **Species toggle**: CORGI / CAT. It opens on the side you'll play: CATS team → cat; adventure → corgi.
- **Progress**: a level badge, an XP bar with `150 / 300 XP`, and the next reward ("Next looks at level 6: Sable +1").
- **Slot tabs**: COAT / NECKWEAR / TAUNTS.
- **Grid**: a 4-column tile grid. Each tile has:
  - a preview:
    - coat: a colour swatch from the style tokens (tricolor saddle, merle dapples, tabby stripes, calico patches, siamese points);
    - neckwear: an SVG glyph (the team collar takes the team colour);
    - taunt: the pack's first line as a speech bubble;
  - the name;
  - a tag: ✓ WEARING, or 🔒 + C3's `unlockHint` ("Reach level 6", "Gold paw: The Garage Job", "Win a Core Rush").
  - NEW looks get a red corner badge.
- **Footer**: a status line and the ‹ CLASSES (or ‹ CHAPTERS) back button.

**Equipping**: click, Enter or pad A.
- It saves at once: "Tricolor on. You wear it from your next spawn."
- A locked tile shakes and the status explains: "Apex Hunter is locked · Gold paw: The Porch Siege".

**NEW badges**: they show for the visit on which the locker opens, then count as seen.

**Keyboard and gamepad**:
- Every control is `[data-nav]`, so the menu's `navMove` and `PadNav` drive it; Esc / pad B go back with PLAY focused.
- Locked tiles are `aria-disabled`, **not** `disabled`, so keyboard and pad players can reach them and read the hint.
- Focus stays on the same tile across repaints.

**Previews**: swatches and glyphs only, no second renderer. The swatch colours come from `style-tokens.js` (C3's coat table was in flight; swapping to it later is a one-function change in `coatSwatch`).

### Reward card

## 6. Known issues and follow-ups
- **`net.spec` under heavy load**: it fails with and without these changes (A/B in §5). Rerun it on a quiet machine before trusting either result.
- **Pre-profile device + first chapter before any profile load**: the paw is paid as retro XP, not as a match. This happens only if the menu never loaded the profile before the chapter; `createMenu` loads and saves it at boot, so it does not happen in practice.
- **A paw earned while `recordMatch` was not wired** (before INT6) unlocks its look but pays no XP.
- **Pads** count only the capture moment with you on the pad, not holding time. Holding points are team score.
- **Taunt previews** show the first line only. No audio preview.
- **Coat swatches** come from style tokens, not C3's `Coat` table, so they can drift if C3 retunes a coat.
