## 2. Design

### 2.1 Prediction and reconciliation (`src/client/net/prediction.ts`)
- **Same code as the authority.** `LocalPredictor.create(seed)` builds a private headless
  `Sim.create({ seed, systems: [] })`. That constructs the static world through
  `buildSimWorld → buildStaticWorld(R, world, createWorldData(seed))` (trimesh terrain and props included)
  and configures the character controller exactly like the authority, so nothing is duplicated.
  The local character is a real `SimEntity` from `sim.spawnCharacter` (collider plus `CharacterState` from
  `moveStatsFor`, including `slideTime/slideCooldown/pounding`). One `world.step()` fills the broad-phase.
- **Per predicted tick**, in authority order: `sanitizeInput(cmd)` (the same function the Room runs
  exactly once), `stepCharacter`, `stepWorldEffects` (jump pads, water; the world lane's pure
  per-entity function), `prevButtons = buttons`, `quantizeMotion`.
- **Quantization (the key finding).** Snapshots carry position at 1 mm and velocity at 1 cm/s. Rapier's
  character controller is chaotic within its 2 cm skin, so a 0.3 mm change in `y` can flip
  grounded/blocked a few ticks later. Rewinding to a rounded snapshot therefore diverged by up to 19 cm
  even at 0 ms latency. So the Room rounds every player-controlled character to exactly snapshot precision
  after every tick (`src/host/quantize.ts`), and the predictor does the same after every step. A snapshot is
  then an exact restart point and replays match the authority bit for bit
  (test: max error `0`, not "small").
- **Reconcile per snapshot:** compare the authoritative state at `ack` with our history entry for `ack`. If it
  matches within rounding (2 mm, 5 cm/s, same grounded), there is nothing to do. Otherwise rewind: position,
  velocity, grounded and sprinting come from the snapshot; hidden state (`airTime, jumpBuffer, jumpsUsed,
  jumpHeld, slideTime, slideCooldown, pounding`, `prevButtons`) comes from our own history at `ack`. Then
  replay `unacked`.
- The acked entry stays in history, so a **repeated ack** (the server's input buffer ran dry and it
  re-applied the last input) is measured and corrected instead of silently re-based.
- **Visual smoothing:** the correction goes into a render offset that decays at 30 /s (about 95 % gone after
  100 ms). A correction over 2 m snaps (respawn, kill plane, teleport). Rendering interpolates between the
  last two predicted ticks by the frame's sub-tick phase, so high-refresh displays are smooth.
- **Death** (`EFlag.Dead`) and **riding a vehicle** (`EFlag.Mounted`, since the vehicle moves the rider)
  stop prediction. The authority's state is shown instead, and the next on-foot alive snapshot re-creates
  the character (snap). An entity, class or team change re-creates it too. Predicting driving itself is a
  Wave 2 vehicle-lane topic.
- **Predicted events:** `jump`, `land` and `ability: slide/ground_pound` for the local player are emitted on
  the bus immediately. The authority's copies of those (for the local entity only) are dropped. Every other
  event passes through unchanged.
- **Lazy-loaded:** `import('./prediction')` on `welcome`. Vite puts it in its own chunk (1.68 MB gz,
  it carries Rapier), so the first frame never waits for it.

### 2.2 Authority input pipeline (`src/host/room.ts`)
- Each input is sanitized **once** (`sanitizeInput` is not idempotent for yaw: `x mod 2π` twice ≠ once).
  Stale and redundant seqs are dropped silently. A seq more than 600 (10 s) beyond the last applied one is
  refused as abuse. The first input of a connection sets the sequence base, so reconnects keep counting.
- **Jitter buffer, one input per tick.** A tick with no input repeats the last one (extrapolation) and grows
  the buffer by one. After 15 starved ticks (250 ms) the player gets a neutral input and stops, instead of
  running forever.
- **Catch-up instead of dropping.** If the minimum buffer depth over a 1 s window was ≥ 3, one tick applies
  two inputs. The first goes through the same `stepCharacter` + `stepWorldEffects` + quantize path the client
  uses; this happens only when both inputs have identical buttons, so no fire/jump edge is lost. Latency is
  trimmed with no desync. `MAX_QUEUE` is 16 (sized for a 250 ms frame's burst) and overflow drops the oldest.
  Mounted riders are never caught up or quantized, because their vehicle positions them.
- `class`/`team` switches are rate-limited to 1/s and chat to 2/s. A client can only ever affect its own slot.
  There is no entity id in the protocol, and forged fields are ignored (tested).
- Roster K/D/score reset on match restart: the match rules' `score` event with `reason:'reset'`, with
  `ended → warmup` as a fallback signal (the L3 finding the lead asked for).
- Per-player `net` counters (`starves, catchups, drops, refused, applied`) are exposed via `/stats`.

### 2.3 Remote entities (`net-client.ts`)
- The clock offset follows the least-delayed snapshot arrivals: it moves up fast (25 %) and decays slowly
  (2 %). Jitter is the mean deviation from it. The interpolation delay tracks
  `clamp(2 × snapshot interval + 2.5 × jitter, 67 ms, 250 ms)`, slewed at 1 ms per snapshot (≤ 3 % time warp).
- Past the newest snapshot, entities are dead-reckoned with their velocity for at most 100 ms. An entity
  that moves more than 5 m between two snapshots is treated as a teleport and not interpolated.
- Duplicate or older snapshots are ignored (time never goes backwards).
- `renderTime()` (used for `InputCmd.rt`, lag compensation) uses the adaptive delay, so lag compensation
  rewinds to exactly what was rendered.

### 2.4 Wire and bandwidth (`src/host/wire.ts`)
- `ServerMsg` stays the API on both ends. Only the WebSocket framing is compact, and only for snapshots:
  - `SnapEncoder` per connection sends quantized integer deltas against the previous snapshot on that
    connection (changed fields only, changed entities only) and a keyframe every 60 snapshots.
  - Match state goes as changed fields (`timeLeft` at 0.1 s). Event floats are rounded to mm.
  - Field order and scales are derived from `packEntity/unpackEntity` at load, so the codec cannot drift
    from the protocol.
- This is safe because a WebSocket is an ordered, reliable stream. Emulated `?loss=` is applied after
  decoding, like UDP loss. The offline worker still passes plain objects.
- Clients may ask for `?enc=raw`; the server can default to it with `WIRE=raw`.
- Input redundancy (3 re-sent unacked commands) is used only on lossy links. Transports report `lossy`
  (emulated loss > 0). Over real TCP it is pure overhead: upstream went from 19 to 5.7 KB/s.

### 2.5 Server (`server/`)
- `app.ts`: one HTTP server serving `/health`, `/stats` (`?reset=1` starts a new tick-max window) and
  optional static files, plus WebSocket upgrades on `wsPath` (or any path).
  - Per connection: frame validation, message and byte token buckets, and an abuse score that halves every
    10 s and kicks with 1008 at 20.
  - Timeouts: hello (4001), idle (4000), and dead peer (no message and no pong for 20 s → terminate).
  - Backpressure: snapshots are skipped while more than 512 KB is buffered; congestion that lasts 15 s closes
    with 1013.
  - Limits: per-IP and total connections, optional `ALLOWED_ORIGINS`.
  - Graceful shutdown on SIGINT/SIGTERM sends a notice and closes with 1001.
- `rooms.ts`: named rooms on demand (max 32) share one fixed-rate loop. Every tick is timed; `overruns`
  counts dropped time. A room whose tick throws 30 times in a row is shut down (1011) instead of crashing
  the process. Empty rooms are destroyed after `ROOM_TTL_MS`.
- `static.ts`:
  - Requests: GET/HEAD only, and the decoded path must stay under the root (realpath-checked, so escaping
    symlinks fail too). Dotfiles are refused, as are `..` in any encoding, `\` and NUL.
  - Responses: MIME table (incl. wasm), ETag/304, `immutable` caching for `/assets/*`, and gzip computed off
    the event loop and cached. Extension-less paths fall back to the SPA page.
  - `index.html` gets `<meta name="cvc-ws" content="/ws">` injected.
- `index.ts` is the dev/standalone authority (any path, port 8787). `prod.ts` serves `dist/` with `/ws`
  (port 8080) and refuses to start without a build.
- Config comes from env (`server/config.ts`): `PORT HOST MODE BOTS SEED MAX_ROOMS MAX_CONNECTIONS
  MAX_CONN_PER_IP TRUST_PROXY ROOM_TTL_MS HELLO_TIMEOUT_MS IDLE_TIMEOUT_MS HEARTBEAT_MS PEER_TIMEOUT_MS
  MAX_PAYLOAD MSG_RATE MSG_BURST BYTE_RATE BYTE_BURST KICK_SCORE MAX_BUFFERED CONGESTION_KICK_MS
  ALLOWED_ORIGINS STATIC_DIR WS_PATH WIRE LOG`.

## 3. API for the lead

`NetClient` (constructor unchanged: `new NetClient(transport, opts?)`):

| member | meaning |
|---|---|
| `pushInput(cmd)` | send **and** predict the sampled input. Do not predict separately; there is no second call. |
| `flush()` | once per frame (as now) |
| `interpolated(now)` | remote entities interpolated/extrapolated; **the local entity is the smoothed predicted state** |
| `renderTime(now)` | server time rendered (for `cmd.rt`) |
| `predictedLocal()` | unsmoothed tick-exact predicted state (e.g. muzzle origin), or `null` |
| `prediction` | `{enabled, active, last, mean, p95, max, corrections, bigCorrections, maxCorrection, snaps, replays}` |
| `stats` | `{rttMs, snapshotsPerSec, kbIn, kbOut, pending, interpDelayMs, jitterMs, extrapolating, …}` |
| `canReconnect` / `reconnect()` | reopen the WebSocket and re-join (the server treats it as a fresh join) |
| `setPrediction(on)` | toggle; `?predict=0` in the page URL disables it by default (A/B) |
| `dispose()` | stop timers, free the prediction world |
| options | `now, predict, pingIntervalMs, timeoutMs, redundancy, createPredictor, onReconcile` |

- Bus: `connected` as before. `localSpawn(id)` now fires once the first snapshot with our (new) entity
  has arrived, so its state is readable. `disconnected(reason)` fires once per connection, with readable
  reasons ("kicked by server (policy)", "server shutting down", "connection timed out", …).
- Liveness counts timer periods without a message (stall-proof: a 30 s frame never looks like a dead link).
- `serverUrlForPage()` / `resolveServerUrl(loc, meta)` in `src/client/net/server-url.ts`. First match wins:
  1. `?offline` → worker.
  2. `?server=ws(s)://…` → that URL.
  3. `?online`, or the page was served by `server/prod.ts` (`<meta name="cvc-ws">`) →
     `ws(s)://<host>/ws` (`wss` on https).
  4. Otherwise → worker.

  `?room=<name>` is forwarded as `room` (`[A-Za-z0-9_-]{1,24}`, else `default`).
- `globalThis.__cvc.net`: `connected, transport, localEntity, rttMs, kbIn/kbOut, snapshotsPerSec,
  interpDelayMs, jitterMs, pending, msgsIn/Out, bytesIn/Out, predicting, predErrCm{last,mean,p95,max},
  corrections, snaps, tick, entities:[[id,kind,x,y,z]…]`.

## 4. Exact wiring for `main.ts` (lead)

```ts
import { serverUrlForPage } from './net/server-url';
// replace `const serverUrl = params.get('server');` with:
const serverUrl = serverUrlForPage();            // ?server / ?online / prod-served page / ?room
// Initial facing: 'connected' fires before any snapshot exists; use localSpawn instead of (or besides) it.
bus.on('localSpawn', (id) => { const s = net.latestState(id); if (s) input.yaw = s.yaw; });
// Disconnect UI (HUD lane can render it):
bus.on('disconnected', (reason) => hud.showDisconnected?.(reason, net.canReconnect ? () => net.reconnect() : null));
```
- Optional: at < 10 fps the 0.1 s `dt` cap makes the client produce fewer inputs than the server consumes,
  so the server starves and corrections appear. `Math.min(0.25, frameMs / 1000)` keeps input real-time;
  the server queue (16) absorbs the burst.

## 6. Known issues and limits
- Authority-side forces that are not movement (knockback, explosions, out-of-bounds respawn) are corrected,
  not predicted: smoothed under 2 m, snapped above. In live soaks this shows as occasional > 0.5 m
  corrections.
- Clients below ~10 fps starve the server's input buffer, which repeats inputs and causes corrections; see
  the optional `dt` cap change in §4. Headless SwiftShader (~1 fps) shows p95 ≈ 21 cm for this reason;
  real GPUs don't.
- Offline play downloads Rapier twice (worker chunk 1.69 MB gz + lazy prediction chunk 1.68 MB gz; total
  initial ≈ 3.75 MB gz, within the 5 MB budget).
  - Proposal: switch to the non-compat `@dimforge/rapier3d` (separate `.wasm` URL, shared cache), which needs
    a `package.json` change.
- No per-client relevance culling: the map is ≈ 200 m, and delta encoding already keeps 12 players at
  14 KB/s. Revisit for larger districts.
- Rooms keep ticking their bots until `ROOM_TTL_MS` after the last human leaves (default 10 s).
- The Vite dev server full-reloads e2e pages when files change (parallel agents). The dev-server e2e
  tolerates one reload (re-resolves the entity, re-presses W) plus 1 retry; the prod-server e2e is immune.
  Don't use Playwright `routeWebSocket` to stub HMR: it broke the second page's game socket (the `hello`
  never reached the server).
- `server/app.ts` imports nothing from `src/client` (room-name sanitizing lives in `src/host/guard.ts`).
  `src/client/net/loopback.ts` (test/tool harness) imports `src/host` and is never bundled.

## 7. Protocol proposals (not implemented; lead's call)
- `snap.me?: number[]` (owner-only hidden movement state: airTime, jumpsUsed, jumpBuffer, slideTime,
  slideCooldown, pounding, prevButtons). Not needed today: history plus quantization reconcile exactly. It
  becomes useful if combat/abilities start writing hidden movement state outside `stepCharacter` (e.g.
  resetting `jumpsUsed` on a hit).
- Compact `input` framing (array per cmd) would cut upstream on lossy links (~19 → ~8 KB/s). Needs a
  `ClientMsg` variant.
- Add `export function configureCharacterController(kcc)` in `src/sim` if the lead ever wants prediction
  without constructing a `Sim` (today `Sim.create({systems: []})` guarantees identical KCC config).
