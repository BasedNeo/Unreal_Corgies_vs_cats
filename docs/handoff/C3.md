# C3 handoff: cosmetics (Wave 6)

**Status:** done, not committed (the lead integrates). Players can wear coat patterns true to their species,
neckwear and taunt packs. A look is paint plus one accessory: it never changes stats, the breed (body shape), the rig
or the class gear. So K1's class silhouettes and the team colours keep their read. This is measured, see §4.

What exists:
- the content and pure rules (`src/shared/content/cosmetics.ts`);
- the code that puts a look on any procedural corgi or cat (`applyLook`, or a `look` option at creation);
- a lab (`labs/cosmetics.html`);
- 27 tests.

Wiring is left to others. The profile and unlocks are P2, the locker is U2, and hello → roster → views plus the
taunt pick are N2 (lead). §5 has the snippets for N2.

## 3. API for P2, U2 and N2

```ts
import { COSMETICS, cosmeticsFor, cosmeticById, defaultLook, unlockHint, sanitizeLook, resolveLook, randomLook,
  tauntLines, TAUNT_PACKS, type Look } from '../shared/content/cosmetics';
import { applyLook } from '../client/procgen/cosmetics';
import { createCharacter, prewarmCharacters } from '../client/procgen/characters';

type Look = { coat?: string; neck?: string; taunt?: string };
```

**`sanitizeLook(raw: unknown, species)`** is for untrusted input. `species` is a SpeciesId or `'corgi' | 'cat'`.
- It keeps only own data properties `coat`, `neck`, `taunt` that are strings of 1–32 characters, a known id, the
  right slot, and the right species.
- Everything else is dropped and never echoed:
  - non-objects and arrays;
  - inherited, prototype and getter properties;
  - hostile Proxies;
  - 10 kB strings (never looked up);
  - ids of another slot or species.
- It never throws. The result holds content strings in a fresh plain object.

**`resolveLook(raw, species)`** does the same, then fills every slot with the species default.

**`isValidLook(look, species)`** says whether a look is exactly a sanitized look.

**`defaultLook(species)`**: corgi `{ corgi_red, neck_none, taunt_corgi_classic }`, cat `{ cat_tabby, neck_none, taunt_cat_classic }`.

**`randomLook(seed, species)`** gives bots a full look. It is deterministic per seed and draws from the whole
catalogue, because bots show off what can be earned. About 1 in 3 bots keeps the team collar.

**`tauntLines(look, species)`** returns the lines of the look's pack. It falls back to the classic lines, which are the
existing `TAUNTS`, for any missing, unknown or wrong-species pack.

**`unlockHint(unlock)`** gives locker text such as "Reach level 4", "Gold paw: Yard Day" or "Win a Core Rush".

**`cosmeticsFor(species, slot)`** returns the items in locker order, default first.

**`applyLook(avatar, look)`** changes a look in place:
- The coat repaints the fur. It swaps to a cached body variant, as a new SkinnedMesh on the **same** skeleton; the
  bones and the weapon move across.
- The neckwear replaces the team collar. It is one skinned mesh on the same skeleton that shares the body material.
- The rig, animator state, weapon, class gear, breed, height and silhouette are untouched.
- It is idempotent and returns `false` when nothing changed.
- Whatever it replaces gets a renderer `'dispose'` (as `releaseObject3D` does) and its cache ref is released.
- Unknown or wrong-species ids fall back to the species default.
- `null` restores the seeded classic look, which is also what you get with no look at all.
- Avatars that do not take looks, such as bosses, are left alone and it returns `false`.

**`createCharacter({ species, cls, team, seed, isLocal, look })`** builds straight into a look, with no swap.
`stats.look` holds the resolved look, or `null` for the classic one.

**`prewarmCharacters([{ species, cls, team, seed, isLocal, look }])`** pins the look's body and neckwear too.
Pass the roster's looks at match load. A new coat body is a 20–50 ms cold build the first time it appears.

For U2's locker preview, keep one avatar and call `applyLook(avatar, candidate)` on every highlight change. It stays
cheap once each body has been built.

**Breeds.** The seed still picks the breed: chonk and sphynx cats keep their body under any look, so a sphynx
wearing Calico is a hairless calico. Without a look, the seed also picks the classic coat as before (ginger, the chonk
grey and the sphynx skin exist only there).

## 4. Proof

**`npm run gate:fast`**: `GATE PASS | typecheck:ok boundaries:ok unit:ok`. The unit suite ran 78 files: 665 passed,
1 skipped. That run includes P2's in-flight tests from that moment. `node tools/char-audit.mjs` → all 24 kits PASS,
and `node tools/char-silhouette.mjs` → worst closest pair 0.133, unchanged.

The C3 tests:
- `npx vitest run tests/unit/cosmetics` → 27 passed (13 content + 14 looks). The slowest test takes about 4.6 s at load 11.

**Budgets and style audit.** Every coat × every class × both teams × both tiers, plus every neckwear × every class ×
breeds cat/chonk/sphynx × both tiers, is checked against the char-audit rules:
- triangles within 6,000 (hero) / 3,500 (NPC);
- draws ≤ 6 and bones ≤ 48;
- style-system materials only;
- outline-safe normals under the ink hull;
- crease ink on rigid parts only;
- `stats` equal to what is measured.

Worst cases:
- hero: **5,996 / 6,000**, corgi overwatch with the bow tie;
- NPC: **3,475 / 3,500**, corgi skyraider with the bow tie.

How the budget fits: the neckwear replaces the team collar and its tag or bell. That frees 102 hero / 80 NPC triangles
on corgis and 102 / 72 on cats. The neckwear itself costs:

| | Bandana | Name tag | Spiked collar | Bow tie |
|---|---|---|---|---|
| Corgi | 124 | 120 | 112 | 128 |
| Cat | 124 | 92 | 112 | 128 |

Every item is under the 132 cap.

**Coats only repaint.** For every class, both species, and every coat, a test compares the body with the classic one.
The position, index and skin-index arrays are identical, and only the colours differ. So the silhouettes are the same
by construction.

**K1 silhouette metric.** This uses K1's `silhouetteMasks` / `silhouetteDistance` at seeds 1, 3 and 13 with every
neckwear. Every class pair stays ≥ 0.10 apart. Each pair moves < 0.01, and each class moves < 0.01 from its classic
self. Measured: the closest pairs stay 0.133 (corgi) / 0.136 (cat), with a maximum change of 0.002.

**Team colours.** `readability.ts` measures the share of visible cells, front and back, in the team's vest hue
(royal blue or crimson). It covers both species on both teams, all six classes, and every coat and every neckwear,
at the NPC tier.
- No look adds any enemy-hue cell. Measured: 0 in every case.
- No look costs more than 1 point of visible area. The worst measured cost is 0.7 points, a cat on the cats team with
  any neckwear: the replaced team collar was crimson-tinted.
- Coats cost 0.
- Neckwear colours stay out of every team hue: green 122°, purple 298°, leather, steel, dark teal. Team blue is 217°,
  crimson 351°, gold 42°.

**applyLook.**
- Test: a renderer-style `'dispose'` spy sits on every mesh. Across repeated and changed looks, each replaced mesh
  fires exactly once, the mesh count never grows, and no listeners are added to shared geometry or materials.
- Test: one body and at most one neckwear exist at any time, on the same skeleton; the body stays `root.children[0]`.
- Test: the cache sizes return to 0.
- Test: a look applied in place shares the cached geometry of the same look built directly, and has equal stats.
- In a real renderer (lab `view=swap&every=0.05`, WebGL2 SwiftShader): 111 swaps × 2 avatars. GPU geometries stayed
  flat at 11–13 and the mesh count at 4–5, with 0 page errors.

## 5. For the lead (N2): paste-ready snippets

The look rides the **roster**, never the snapshot, so the snapshot size is unchanged. Bot looks need no network at all:
`randomLook(entity.seed, species)` is deterministic, and the seed is already in every `EntityState`. The sim (taunts)
and the client (views) derive the same look independently.

## 6. Known issues / next
- **Soft patch edges.** Merle and calico patches are per-vertex colours, the same technique as the tabby stripes. Edges
  are soft, and blotchier at the NPC tier.
- **Same patches for everyone.** Every merle or calico of one breed has the same patch layout: the noise works on model
  positions, not on the seed. Seeded patches would need a body per seed and would lose geometry sharing.
- **Hero budget margin is 4 triangles** (5,996 / 6,000, corgi overwatch with the bow tie). New hero gear needs a trim
  elsewhere, as K1 noted.
- **The classic team collar is mostly hidden from the front** by the chest ruff. This predates C3. Neckwear sits
  outside the ruff on purpose, so it shows from the front.
- **Warden with the spiked collar.** Seen from the side, the rear studs peek out behind the cone's back rim. They do not
  cut through it (`close-corgi-warden-spiked-side.png`).
- **Neckwear variants.** The mesh is fitted per (species, breed, class build), because the flap lands on that class's
  chest plate. That is at most 4 items × 4 plans × 6 classes, each built in under 1 ms and shared across teams and tiers.
- **Bots wear locked items.** `randomLook` ignores unlocks on purpose.
- **Classic-only coats.** Ginger, the chonk grey and the sphynx skin now appear only on avatars without a look. After
  N2 that is avatars with no roster look, since every bot gets a `randomLook`.
- **Breeds show through.** A look never changes the seeded breed. Chonk and sphynx cats stay chonk and sphynx, painted
  with the look's coat.
